我的數位腦

AI Personal Collection & Recall System

讓收藏過的資訊
在真正需要時重新回來

我們每天收藏文章、影片、網址與地點。

但時間久了，真正遇到問題時，常常只剩下一個模糊印象：

「我以前是不是看過一篇講這個的文章？」

真正的問題不是沒有地方收藏。

而是：收藏之後，還能不能被重新找到與利用？

PROBLEM

收藏很容易，重新找到很難

資料散落

文章、影片、LINE、地點存在不同地方。

收藏後沒有整理

當下覺得重要，但沒有時間重新分類與摘要。

只剩模糊記憶

過一段時間後，可能只記得：「好像以前看過一篇相關的內容。」

因此，我最初想解決的問題不是：

怎麼收藏更多？

而是：

怎麼讓以前收藏過的東西，在真正需要時重新出現？

PRODUCT FLOW

從收藏到重新使用

CaptureUnderstandStoreSearchRecallAsk

  1. Capture

    先把值得留下的內容存進來。

  2. Understand

    讓 AI 協助理解、分類與整理。

  3. Store

    保存結構化資料，同時保留原始來源。

  4. Search

    知道關鍵字時快速找到。

  5. Recall

    只剩模糊印象時重新召回收藏。

  6. Ask

    直接根據自己的收藏整理答案。

PRODUCT DECISIONS

做了哪些取捨

為什麼沒有一開始就做圖片 CDN？

Public Preview Image + Safety Validation + Graceful Fallback

Portfolio MVP 不需要先承擔：

Object Storage ／ CDN ／ Cache ／ Cleanup ／ Copyright ／ Image lifecycle

先做能提升產品體驗的最小版本，不因 UI enhancement 擴大整個基礎架構。

為什麼不把所有收藏全部丟給 LLM？

  • Token cost
  • Latency
  • Data exposure
  • 結果難以解釋
  • 模型可能產生不存在來源
有限語意理解RetrievalRanking真實收藏結果

有些功能，暫停比硬做更重要

原本希望加入 YouTube Transcript enrichment。

實際驗證後，遇到平台 PO-token 與存取限制。

因此功能標記：PAUSED / BLOCKED。核心收藏流程仍繼續交付。

產品管理不是把所有想到的功能做完，而是知道什麼時候應該停。

WHAT I LEARNED

我真正學到的事

一開始，我以為最大的挑戰會是：

「AI 功能怎麼做出來？」

做完整個產品後，我發現真正困難的是：

怎麼讓一個 AI 功能變成可信、可控、可使用的產品流程。

權限與個資

誰可以看到什麼資料？

人工確認

哪些結果一定需要人確認？

既有系統整合

如何接回 ERP、報表、LINE 或內部流程？

User Adoption

工具真的替使用者省事了嗎？

這些問題，比單純選擇哪一個模型更重要。

AI 的價值，不只是產生更多內容

而是幫助我們重新使用那些：
已經看過、已經判斷過、曾經覺得重要的資訊。

這就是我做「我的數位腦」的原因。
